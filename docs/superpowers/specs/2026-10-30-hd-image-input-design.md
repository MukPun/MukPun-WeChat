# 高清图片输入

用户要求微信图片自动获取真实高清版本，不需要在客户端手动点开，单张输入约25MiB。

优先原图，原图缺失、已知不可用或超限时尝试标准图；不自动使用缩略图冒充高清。Native quality=best 会优先返回任意已缓存资源，不能用它实现原图优先；必须绑定具体原图/标准图 assetId 与 quality。校验账号、父消息、资源、下载作业、字节数、SHA256 和实际质量。完整性/身份错误不允许通过降级隐藏。下载失败保留可转发的问题文字，不中断文本服务。

输入上限25MiB、边长16384、总像素100000000。图片输出8MiB、语音源8MiB不变。Native v1.2.0与现有登录、未知发送审计、去重不变，无需Native重启。新增图片输入分块使用每帧不超过256KiB、每块不超过64KiB、仅一块等待确认；控制器不组装全图。host完整核验后才持久接收和确认SSE游标。分块超时180秒，下载共享60秒截止。

AstrBot现有Hypercorn WebSocket默认16MiB。超过128KiB的输入由OneBot工作进程在专用临时图片目录保存原始字节，事件只携带file:////AstrBot/data/temp/wechat-hd-input/<sha>.<ext>，不改AstrBot代码/配置或Docker挂载，不新增HTTP端口。只将这一专用目录额外绑定进本项目OneBot隔离进程。临时文件0600，目录0700，root将该专用目录绑定给当前动态UID；与已有AstrBot data挂载复用，容器root可读。路径固定且仅摘要文件名，拒绝符号链接。文件缓存512MiB/256项/600秒，周期清理过期项；容量不足只拒绝新图片并保留文字，不能删除未过期文件。队列继续32条/2MiB、身份及动作去重保持原值。

Native读取进程内存max/high256/192MiB；正式OneBot图片输入进程512/384MiB；控制器仍64/48MiB。传统无高清输入试验默认限额保留。Native父组3GiB/临时卷2GiB、500MiB媒体维护策略保留；高清输入容量门禁同步预留25MiB下载及数据库副本。所有精确隔离校验同步更新。

仅验证改动范围：原图优先与标准回退；25MiB边界；分块身份/顺序/摘要/确认/超时；临时文件完整字节/路径/容量/过期；真实合成CQHttp接收文件且WS事件有界；现有文字、图片输出、语音路径的必要回归。部署只短暂停启本项目桥、保留Native和登录。真实验证优先读取用户已收到图片，不向联系人发送诊断消息，不自动调用模型。公开仓库仅保存源码、文档和合成验证。
