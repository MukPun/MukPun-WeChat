## 协议兼容

新版删除了旧的 GET /messages/{id}/quote。桥改读父消息详情的 quote 字段，仅接受同账号、同会话、同父消息且 type=49、appMessageType=57、引用为 type=3/state=embedded/embeddedImage=true 的情况；再以父消息 ID 读取媒体。撤回、缺失、非图片或外部会话引用明确拒绝，不检索历史原始消息替代收到的引用内容。

该适配覆盖普通图片及同会话引用图片。Native 的 image_variants、fit_jpeg 与旧版本一致，锁定的 image 库均为 0.25.10；已有图片变体放大缺陷没有随版本升级修复，不能保证任意素材发送成功。

## 保存资料与未知发送

普通恢复继续拒绝待发送或未知作业。显式迁移入口 resume_quarantined_native.py 只读取私有、一次性票据，并以排他锁覆盖票据消费与所有者完整生命周期；实际复制的归档流必须匹配票据摘要。

迁移例外只允许账号目录及完整行摘要匹配的唯一 needs_review/submitting、attempts=1、cancel_requested=0、retryable=0 图片作业继续保持未知。作业不更新、不重新入队；额外作业、待发文字、WAL 待发记录、绑定改变或作业缺失仍阻断恢复。原控制器、PID、cgroup 和私有目录检查保留，进程准入仅额外接受同检出中迁移入口的精确参数。

恢复复用完整保存资料，不隐式 initialize、扫码或 logout。保存凭据是否被服务端接受必须在私有部署流程中核对，离线验证不能保证某个真实账号一定恢复成功。

## 启动校验与资源契约

v1.2.0 的 wechat-store/admission.rs::open_prepared 会创建两份 SQLite 校验副本。源码为此提供受限启动空间；下表是代码配置，不能据此推断任何实例当前状态。

| 源码约束 | 上限 |
| --- | --- |
| Native 私有临时卷 | 2GiB，缓存预算 500MiB |
| Native 硬内存 | 2560MiB |
| Native 父 cgroup 硬内存 | 3072MiB |
| 单文件 / 保存资料 | 768MiB / 1GiB，归档 1028MiB |

图片预算保留额外启动空间及当前数据库的两份副本，新上传增长也同时预留其两份副本。空间不足时拒绝新的媒体工作，不能依靠删掉未知记录或取消保护恢复服务。现行容量验证入口区分临时卷大小与单文件、保存资料上限。

输入与输出沿用各自原有契约：

- 微信到 AstrBot：单图载荷最大 128KiB；优先使用合规缓存版本，必要时请求缩略图。
- AstrBot 到微信：静态图片源最大 8MiB，同时受尺寸、像素、格式和剩余容量校验约束。

输入的容量计算使用 128KiB 输入契约，不误用 8MiB 输出契约。这项修正不降低任何已有文件大小上限。

## 测试范围

迁移实现的完整合成回归为 734 项。最后的输入契约修正覆盖预算 11 项、图片 91 项、全群 5 项；Linux 独立受限回归 324 项通过、零跳过。发布审计和独立代码审查通过。测试不需要真实模型或额外发送消息。

合成测试覆盖协议、路由、持久队列、去重、回执、恢复门禁和隔离；实际微信登录与文字、图片交付须通过实例私有验收记录核对。

## 实例切换检查

1. 在本地完成相关测试及发布审计；核对源代码和资产摘要。
2. 核对队列、未决动作及精确隔离条件，备份完整配置、会话、审计、预算和一致数据库。
3. 只停止项目自身桥、工作进程及 Native；确认精确单元与 cgroup 已清理，保留原始失败回执。
4. 复用完整保存资料，先核对身份、密钥、未知作业和认证结果，再更新隔离绑定并启动桥。
5. 核对实际版本、资源、SSE、AstrBot 与随后自然流量回执。失败时保留证据，不自动扫码或重试未知发送。

若旧进程保存的环境基线已经过时，应保留原回执，独立核对本次精确资源清理及当前基线；不能将旧失败记录改写为成功。不得修改其他业务服务、宿主网络或路由来满足验收。
