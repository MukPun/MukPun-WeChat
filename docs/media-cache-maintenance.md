# 500MiB 媒体缓存维护

图片、语音持续发送会在 Native SQLite 留下上传源。旧规则只在普通启动时回收图片源，常驻会话及隔离恢复未覆盖，语音源也未纳入。新的独立 timer 每分钟检查一次，覆盖已确认完成的图片和语音上传源。

缓存预算为 **500MiB**，按 Native 临时卷总占用计算，包含上传源、数据库、资料及 SDK 媒体数据；这是维护触发目标，不是单张图片上限。隔离临时卷扩大到 **2GiB**，按需分配内存，为 SQLite 的两份启动校验副本预留空间。Native 单文件上限 768MiB、快照源 1GiB、归档 1028MiB；Native guest 内存 max/high 为 2560/2304MiB、父组为 3072/2816MiB。CPU、任务、网络隔离不变。图片输出 8MiB、图片输入 128KiB、语音源 8MiB 不变。

达到 500MiB 或受保护的可用空间低于 48MiB，且桥连接正常、状态新鲜、空闲至少 60 秒、无待处理队列、未决发送及媒体外连时，才估算回收量。至少可回收 1MiB 才停启。成功维护后至少间隔 5 分钟；无收益或失败后至少间隔 1 小时。

维护先停桥并确认工作进程退出，再停止 Native，要求明确的正常停止和最终快照保存证明。备份原快照及审计后，只在离线副本回收完成且至少 60 秒的上传源并 VACUUM。图片保留摘要、上传读回和服务端确认要求；语音要求所有分段接受、唯一且匹配的服务器标识、消息投影及官方媒体写回完成。未完成、部分成功、未知及外部上传源不清理。

其他数据库表、密钥、消息、回执、去重、SDK assets、apply_intents 和 managed profile 均保留。SQLite WAL/journal 在副本中正常恢复并合并。唯一已获批准的隔离发送必须保持完整行和源绑定不变；任何新未知发送都会阻止维护。恢复只使用保存登录，核对密钥、不生成二维码，再恢复桥。失败后的不明确恢复不会自动重试或回退旧快照。

自动备份只保留最近 3 次，人工和发布备份不受影响。维护状态与备份均在项目外 root 私有目录；公开仓库不保存实例资料。

```bash
# root 安装本项目 service/timer；每分钟检查，不等于每分钟回收
python3 -I -B scripts/maintain_media_cache.py install
systemctl status astrbot-wechat-media-maintenance.timer
# 停用自动检查，不停止桥或 Native
systemctl disable --now astrbot-wechat-media-maintenance.timer
```

扩大容量和回收上传源可以延长运行，但消息历史和官方缓存仍会增长；如果无法回收足够空间，容量门禁会暂停新媒体，保留文字转发。持续忙碌时维护会等待空闲，实际占用可能暂时超过预算。硬中断留下的维护记录需复核，避免反复重启。Native 单次七天租期仍保留。
