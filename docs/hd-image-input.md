# 高清图片输入

桥优先请求微信提供的 `original` 图片资源。即使缩略图或标准图已缓存，也绑定原图的 `assetId` 和 `quality=original` 下载，不使用会优先返回任意缓存图的 `quality=best`。不需要手动在微信客户端点开。

原图缺失、已知不可用、超出大小限制或已知下载失败时，可尝试标准图。桥不自动回退到缩略图，也无法还原微信服务器未提供的原始拍摄文件。资源身份、实际质量、长度或 SHA-256 核对失败时拒绝该图片，保留可转发的问题文字。微信原生 `type47` 表情包输入仍未启用。

Native 自动下载可能在中转取得临时 CDN 许可前以 `transport_unavailable` 失败。对明确可重试的这类任务，中转先只读核对原有下载任务的账号、资源和任务 ID，再在同一读取期限内最多重试一次；任务本身的尝试次数仍小于 3。不会重试发送任务、身份不匹配或完整性失败。

读取 Native 媒体接口时，GET 单次等待上限为 20 秒；仅对连接中断、超时等暂时传输错误最多尝试 3 次。所有读取和重试仍共享原有 60 秒期限及单图 120 次 HTTP 尝试预算；POST 不自动重发，Native 拒绝、格式或完整性错误不走网络重试。

单张输入限制为 25MiB、边长 16384、总像素 100000000；图片输出和语音来源仍分别为 8MiB。一次读取共享 60 秒截止时间；下载的临时网络许可在高清模式下最多 65 秒，仍绑定同一 Native 实例、同一作业和其实际公网 HTTPS 目标，完成或失败即恢复原许可。

Native 读取进程与 OneBot 进程之间以最多 64KiB 的原始数据分块逐一确认，IPC 单帧仍最多 256KiB。控制器只逐块核对长度和摘要，不组装整张图。接收端在完整核对后才写入队列和确认 SSE 游标；分块总期限为 180 秒。

现有 AstrBot WebSocket 有 16MiB 限制，因此大于 128KiB 的输入保存为专用共享临时文件，事件只携带 `file:////AstrBot/data/temp/wechat-hd-input/<sha256>.<ext>`。这与 AstrBot 自己的文件组件格式一致，保留图片字节。只在既有 AstrBot 数据挂载下使用该项目专用子目录，并将其单独绑定给 OneBot 工作进程；不改 AstrBot 代码、配置或 Docker 挂载，不新增 HTTP 服务。

文件缓存限制为 512MiB、256 项、600 秒有效期。目录 0700，文件 0600，只接受固定摘要文件名及受支持扩展名，拒绝符号链接、硬链接、异常所有者和权限。每次重启先将缓存归还控制器，再记录已验证的新动态 UID，最后交接文件和目录；中途退出可继续恢复。缓存满时拒绝新图片并保留文字，不提前删除未过期文件。既有 32 条 / 2MiB 队列、身份映射与动作去重不变。

正式 Native 转发进程内存 max/high 为 256/192MiB；启用高清输入的 OneBot 进程为 512/384MiB，单文件写入上限 32MiB。控制器仍为 64/48MiB。Native SDK、父资源组、2GiB 数据卷和 500MiB 媒体维护预算保持原值；新输入容量门禁预留 25MiB 下载及数据库副本所需空间。

定向验证覆盖原图优先、标准回退与身份拒绝、25MiB 分块边界、文件缓存清理、UID 交接中断恢复、CQHttp 事件大小及既有文字回执。真实容器只读检查使用合成文件；现有图片的媒体元数据和原图读取可独立核对，不补发历史图片，不调用模型。
