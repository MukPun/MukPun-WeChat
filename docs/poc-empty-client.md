# 空账号 Linux 原生端启动实验

## 目的与范围

只验证固定版本原生微信接入端能否在受限 Linux 环境内启动、提供健康接口，并保持账号列表为空。这不验证微信登录、群消息收取或发送，也不对接 AstrBot。

前置保护机制由用户实际运行系统级探针验证通过。本实验启动前仍重新检查真实隔离状态；任一失败就不运行第三方文件。

## 固定输入

- 上游：[agent-wechat v1.0.0-beta.8](https://github.com/thisnick/agent-wechat/releases/tag/v1.0.0-beta.8)。
- 文件：`wx-v1.0.0-beta.8-linux-x64-gnu`。
- 大小：28,757,872 字节。
- SHA-256：`fde2920e71e0e20b926498b8c306a5064527afa5abd2b558eff9cefa0cce478e`，本次通过 GitHub 发布资产元数据复核。
- 下载由系统 curl 完成，限速 128 KiB/s、最大响应 30,000,000 字节、禁止 HTTP 降级、无自动重试，并受独立 CPU/内存/运行时长限制。
- 下载后的文件保持 0600、不直接执行；系统级启动器复制到 root 所有的临时目录后再次校验，并以只读绑定提供给实验。
- root 所有的只读副本在宿主 /var/tmp 的随机私有目录额外固定占用约 28.8 MB 磁盘，不计入 128 MiB 测试 cgroup；复制前检查至少剩余 128 MiB、允许执行，并对复制进程设置 30,000,000 字节文件硬上限。结束时删除该副本。

## 实际保护措施

| 项目 | 限制 |
| --- | --- |
| 身份 | 独立 DynamicUser，禁止额外 capabilities、权限提升及 namespace 创建 |
| CPU | 一个核心的 20%，周期 100ms，Nice=19 |
| 内存 | high=96 MiB、max=128 MiB、swap=0 |
| 进程/线程 | 最多 32 |
| 时长 | 运行上限 45 秒，停止宽限最多 3 秒，无自动重启 |
| 网络 | PrivateNetwork，只能看到独立 lo；没有宿主机端口和微信外网连接 |
| Unix socket | 禁止新建 AF_UNIX socket，额外屏蔽 Docker/containerd 和用户运行目录 |
| 文件系统 | 系统只读、用户目录隐藏、程序和控制器只读 |
| 临时数据 | 单元内 /var/lib 为 32 MiB、1024 inode 的独立 tmpfs；/tmp 和 /var/tmp 不可访问，/dev/shm 为 4 KiB 只读挂载 |
| 子进程环境 | 环境变量白名单；HOME/XDG/TMP 均指向私有临时树；TOKIO_WORKER_THREADS=1 |
| 日志与凭据 | 子进程标准输入输出关闭；控制器不输出 token、账号正文或原始客户端日志 |

控制器会验证真实挂载、cgroup、身份和网络，而不只检查启动参数。临时目录由动态用户创建；账号 token/key 只能生成在私有 tmpfs 中，实验结束随命名空间销毁。

## 验证流程

1. 验证全部保护措施及只读二进制校验和。
2. 在同一个受限单元内启动 `wx ... serve`，不创建账号，不调用任何登录接口。
3. 在私有回环网络访问 `/health`。
4. 检查未认证账号查询被拒绝；使用本次临时 token 查询账号，要求返回空数组。
5. 验证 native 版本与 API 状态。
6. 只终止本次创建的子进程；系统单元退出后销毁临时挂载，清理已知的 root 临时文件。
7. 复核 frpc、dockerd、containerd 的 PID/启动时间和 SSH 连通性。

成功标识为 `EMPTY_CLIENT_STARTUP_VERIFIED`。如果失败，不自动提高资源、放松隔离或切换到宿主网络。

## 状态

固定文件已限速下载并校验：约 3 分 38 秒，下载进程峰值内存 1.8 MiB。下载文件为 0600，不直接执行。

第一次受限启动在第三方程序执行之前被保护门禁拒绝：`/tmp` 与 `/var/tmp` 的容量检查失败，其余身份、网络、Unix socket、资源和只读文件检查均通过。该单元约 510 毫秒退出，峰值内存 3.1 MiB，未执行微信端。

随后仅运行系统 Python 的 `--isolation-only` 诊断，证实 DynamicUser 隐含的 PrivateTmp 将上述两个目录绑定成宿主 ext4 的私有子目录，覆盖了预期的 tmpfs；因此总容量不是 32 MiB。修正方案不升配、不放松保护：把唯一可写工作盘移至单元私有 `/var/lib` tmpfs，并直接屏蔽 `/tmp` 与 `/var/tmp`。此修正仍须先通过仅隔离验证，之后才允许空端启动。

上述为过程中的保护拦截记录。实验最终结果如下；没有创建微信账号或修改现有 Docker、frpc、AstrBot。

新的工作盘与临时目录屏蔽方案通过了独立预检，全部保护条件为 true。首次实际启动尚未进入客户端代码：只读副本所在 /run 本身为 noexec，阻止 execve。保留该挂载策略不变，仅将 root 只读临时副本移到 /var/tmp 随机目录；沙箱内 /var/tmp 仍不可访问，副本只通过 /opt 只读绑定暴露。

## 最终结果：通过

最终单元：`astrbot-wechat-empty-probe-1792693129-1830876.service`。

- 全部隔离门禁通过，包括新增的二进制执行挂载检查。
- 临时目录准备完成，空账号客户端实际启动。
- `/health` 返回正常。
- 临时 token 文件权限与所有者符合要求；未输出或保存 token 到项目。
- 未认证账号查询被拒绝；认证查询的账号列表为空。
- 状态为 ready，backend=native，version=1.0.0-beta.8。
- 自己创建的客户端子进程完成退出后，控制器输出 `EMPTY_CLIENT_STARTUP_VERIFIED`。
- 单元结果 success、exit=0；运行约 585 毫秒、CPU 130 毫秒、systemd 报告单元峰值内存 3.4 MiB、swap=0。此峰值不包括已单独披露的临时只读文件副本和外层准备工作。

## 清理与业务边界复核

- frpc PID 1026310（2026-10-18 18:49:20 启动）、dockerd PID 1201、containerd PID 949，以及先前观察的全部 Docker 端口代理 PID/启动时间前后相同。
- 没有执行 Docker API/CLI 或 frpc 管理命令；没有修改其配置、路由、防火墙、现有 AstrBot 配置。
- 最终单元已回收：LoadState=not-found、ActiveState=inactive；没有残留本项目测试单元、wx 进程或宿主 26174 监听。
- /run 与 /var/tmp 中没有残留本项目 root 临时副本目录；宿主没有 /var/lib/astrbot-wechat-poc 账号数据目录。临时 token/key 仅在已销毁的私有 tmpfs 中存在。
- 最后复核可用内存约 29 GB、swap=0，内存 PSI some/full 的近期平均值均为 0；SSH 连接正常。
- 当前交互 sudo 会话已失效并关闭。凭据仅用于交互认证，未加入项目文件、脚本、环境变量或上传材料。
- 服务器项目目录仅保留探针脚本、说明及校验过的公开版本文件（0600），没有常驻服务。

执行期间出现过一次下载前 SSH 连接超时，以及一次空闲交互 SSH 会话重置；重连后均先复核服务 PID/启动时间，未观察到进程重启。这些观察不能替代完整业务可用性监控，也不能据此承诺共享宿主机绝对零风险。

23 项完全 mock 的离线单元测试通过，覆盖隔离失败拒启、只预检不执行、响应大小限制、非空账号拒绝和只清理本次子进程等行为。

## 结论与下一步

已验证最小技术猜想：该固定 Linux 原生端能在此服务器的严格离线隔离与资源限制内提供空账号 API，并干净退出。

尚未验证微信账号登录、同步、@识别、群消息读取或回发。下一步应单独设计有界联网扫码实验；不能移除 PrivateNetwork 后直接沿用当前脚本，也不能因此修改现有 Docker/frpc。
