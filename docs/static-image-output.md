## 支持范围

OneBot `send_private_msg` / `send_group_msg` 接受一张 `image` 段，可附同会话 `reply`。AstrBot 的 aiocqhttp 适配器将本地图片转换成 `base64://`，桥不打开 AstrBot 路径、不挂载容器目录、不下载任意 URL。

源图片支持静态 PNG、JPEG、WebP，最大 2MiB，宽高各不超过 2048，像素不超过 2×1024×1024。PNG 校验 CRC、尺寸、最多64KiB分块输出的有限解压，拒绝 APNG；WebP 拒绝动画标记。Native SDK 可能重采样并转换为 JPEG，不能承诺源文件逐字节不变。图片输入仍维持原来的 128KiB 上限。

动图、GIF、原生 sticker、图文混合、多图、CQ 图片字符串和超限素材暂不支持，返回带原 `echo` 的明确失败，不部分发送文本，不将已拒绝请求计为不确定提交。`can_send_image=yes` 表示上述受限单图能力。

初版只读检查图库180张素材，其中110张符合当时1MiB/1024限制。后续兼容修复已覆盖6张常见超限素材，尚未将新版本结果推广为任意素材均可发送；2MP以上、GIF和动图仍可能被拒绝。插件 `convert_static_to_gif=false`，未修改插件或图库。

## 完整链路与超时处理

`AstrBot image → OneBot action → 持久动作去重 → 受限 IPC → Native uploads → sends job → 服务器回执 → 消息/媒体投影校验 → OneBot 回执`。

旧工作进程把 WebSocket action 解析预算错误地替换为 Native IPC 的 256KiB，较大 base64 请求会在返回 API 结果前断开，产生 `WebSocket API call timeout`。现将 action 上限独立设为 4MiB，WebSocket 队列为 1；严格解析失败尽可能保留唯一可信的顶层 echo，不能确认 echo 时不猜测。测试使用真实 aiocqhttp API future 验证超时问题，并验证后续文本仍能发送。

Native IPC 单帧仍为 256KiB。超过 128KiB 的图片通过 `image_begin → image_chunk/ack → image_commit` 传输，每块最多 64KiB 原始字节，只保留一个待确认块。控制器和 Native 均核对顺序、总大小、SHA 和最终格式，完整提交前不调用上传或发送接口。小图片沿用单帧路径。Native 图片发送使用独立线程，SSE 仍可接收消息。

上传和发送 POST 均只提交一次，使用稳定幂等键；已受理作业只做有限 GET 核对，未知结果不重发。图片保存独立审计，保留文本已接受回执作为自身身份校验依据。
