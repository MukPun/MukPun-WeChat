# AstrBot表情图片发送失败与错误隔离

以下记录为早期尚未支持图片输出时的修复。后续已启用[静态图片输出及超时修复](static-image-output.md)，当前范围和验收状态以新记录为准。

2026-10-27。用户提供01:06:13的`meme_manager`错误：`send_private_msg`返回`1400 / invalid_request`，调用路径最终为`MessageChain([image])`。

## 原因与能力范围

现有桥支持微信普通图片输入交给AstrBot，向微信发送则只实现文本。`can_send_image`一直返回`yes=false`。图片发送请求中的OneBot `image`段不在支持范围，旧发送解析器抛出`unsupported_segment`，被统一转换为`invalid_request`。

只读核对已安装插件的`_send_meme_image`，该路径直接通过`context.send_message`提交图片；把文件改成base64也不会补齐桥的图片发送能力。此次未修改插件配置、模型或SDK，也没有扩大此前暂缓的微信type47表情包接收范围。

## 本次修复

- 为不支持的输出消息段增加独立错误类型，仍返回失败，`retcode=1400`，`message/wording=unsupported_message_segment`，保留原echo；不伪造发送成功。
- 该验证发生在Native提交之前，图片、CQ图片串及图文混合请求都不会产生部分文本发送，不读取图片URL、文件或base64正文。
- OneBot工作进程将这一确定的未提交拒绝报告为`action_unsupported`；控制器增加`unsupported_actions`计数，保持后续文本转发。旧逻辑将全部非零发送结果都报告为`action_rejected`并停止桥，过度扩大了这类拒绝的影响。
- 真实不确定发送、状态不可验证等其他错误仍保持原停止并待核对策略，不放宽自动重发限制。
- `can_send_image`仍为false。真正向微信发送图片或表情图片尚未实现；此次修复不消除插件对不支持能力的报错，只明确原因并隔离对转发服务的影响。

用户提供的01:06:13报错，与此前01:06:45桥自动恢复的时间相符，代码也确认旧拒绝处理能导致停止恢复；但该历史轮次缺少完整退出日志，因此不把时间关联当作逐条恢复原因的最终证明。
