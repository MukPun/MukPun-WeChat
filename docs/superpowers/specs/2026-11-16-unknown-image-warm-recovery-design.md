# 单笔未知图片发送后的暖恢复设计

用户已明确许可：对本次图片输出保留结果未知、隔离且不重发，在证明恢复快照、处置账本、接收锚点与原微信会话后，仅恢复桥。用户没有看到额外图片不证明未送达；不以此改写回执。

## 当前边界

本次 OneBot 1408 与 live 图片审计、Native needs_review/submitting 作业和 ledger revision 5 的 unconfirmed_quarantined 条目精确绑定；旧清单只覆盖 4 项，owner 保存快照覆盖 5 项。桥进程仍在线但暂停投递，Native 在线。禁止旧清单直接恢复、重发任何消息、改写审计或桥动作、fresh login、重启 Native、修改配置与群开关。

## 顺序和失败行为

1. 只读核对当前服务、原 owner/Native 身份、唯一未知动作、作业/审计/账本指纹、媒体策略、真实接收锚点与零私聊积压。保存本次确认和精确文件/数据库证明，不能读取或输出正文、令牌、原始身份。
2. 停止且只停止项目桥；核验准确停止结果、全部旧 worker/cgroup 退出和原 Native 未变。在排他锁下持久备份恢复清单指针、账本、审计、journal、配置、完成回执和一致桥数据库，记录摘要。捕获和网络活动未结束时拒绝继续。
3. 桥停稳后，用现有 `ForwarderCapture` / `recovery_checkpoint.capture` 构建新一代清单，严格验证原有自我身份、当前接收锚点、会话资料指纹、快照与新作业唯一绑定、所有待决项均已被账本覆盖。现有两代下界只允许在原子清单指针提交后按现有实现推进。
4. 复核新清单实际包含 5 个被覆盖项、含本次精确作业，原 54 个桥侧未知结果保留，数据库/账本/配置/旧审计保持，真实 GET 身份/锚点和私聊零积压仍成立；只通过现有 warm-only guard 单次启动桥。不修改 journal 以绕过拒绝；如 journal 变为 requires_review 或任何证明失败，保持停止并汇报。
5. 只读验证 Native、SSE、WS、身份、受限配置、无新待决以及新清单；不发消息、不触发模型、不重发未知作业。保护解除不代表已查明图片是否送达、停机异常或图片失败根因。

## 验证

受限一次性脚本及合成测试只使用非生产假数据：覆盖正常准入、错误账本/快照/身份/锚点/积压、旧清单缺少新项、重入与副作用顺序，确认失败前不调用 stop/capture/start，capture 失败绝不 start。真实执行逐阶段绑定新证据；保留实际错误和中断状态，不扩大测试范围。

## 只读预检发现的媒体租约

运行中的桥持有精确 media-egress.lock 和一个超出基础策略的临时地址，状态显示 egress active 但无在途媒体；这是受限预热租约，不能在桥外手动覆盖。预检仅在地址集合包含完整基础策略、恰好多一个地址且该锁和文件描述符均由当前 bridge 主 PID 持有时允许继续；停止由控制器自己的 finally 关闭租约。停止后必须真实恢复基础策略、旧 worker 与捕获任务均退出且完成回执干净，否则不捕获、不启动。人工直接 set-property、忽略清理失败或掩盖旧状态均不允许。候选归档进入原清单发布流程前，还要检查该归档包含与现有第 5 条隔离记录精确绑定的作业并通过五项准入。
