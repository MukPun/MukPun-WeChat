# 媒体缓存自动维护实施计划

> 按 executing-plans 在当前已隔离工作区内逐项执行；用户已批准空闲时短暂停启维护。测试仅覆盖变动部分。

**目标：** 自动回收已确认完成的图片、语音上传源，避免媒体压力导致整个转发链路中断。

**架构：** 保持离线快照回收；独立 timer 检查空闲与容量并协调本项目桥/Native 保存、回收、复用登录恢复。不可回收数据保留，媒体门禁及文字转发继续工作。

## 全局约束

图片输出 8 MiB、输入 128 KiB，语音源 8 MiB；Native 数据卷上限 2 GiB、单文件 768 MiB、快照源 1 GiB/归档 1028 MiB；媒体缓存预算 500 MiB。数据卷按需使用内存，Native guest/parent 内存上限分别 2560/3072 MiB。未知发送、密钥、官方缓存、消息、回执和去重不修改，不重发。空闲 60 秒，缓存占用达到 500 MiB 或安全余量低于 48 MiB，最小收益 1 MiB，成功冷却 5 分钟，无收益/失败冷却 1 小时。自动备份最多 3 次。

## 1. 扩展回收完成证明

修改 scripts/media_cache_maintenance.py、tests/test_media_cache_maintenance.py。先增加已接受语音、部分接受、错误服务器绑定、外部源及压力配额用例并确认失败；扩展类型化完成证明并允许压力保留字节数参数。现有图片证明不放宽，非源表及归档成员保持一致。仅运行该测试文件。

## 2. 维护策略

新增 scripts/media_maintenance_policy.py、tests/test_media_maintenance_policy.py。实现固定阈值、空闲、队列、审计、租约、新鲜度、冷却及回收收益判断。先测试压力但正在发送、陈旧状态、存在未知任务和无收益场景，逐项实现。私有状态不得包含消息内容。

## 3. 维护协调器

新增 scripts/maintain_media_cache.py 与对应合成测试。采用私有排他锁、预估副本、停桥/工作进程门禁、Native 保存、快照备份、离线清理、非源数据摘要验证和登录复用。已有获批隔离只接受原完整行和源绑定；任何其他未知任务阻断。恢复失败保留明确阶段及原快照。自动备份保留最近 3 次。编写精确 systemd service/timer 文本和安装入口，只管理本项目新建单元。

## 4. 文档与上线

更新缓存说明。运行以上新改测试及与启动/隔离相关的必要用例，审核源码和发布内容。发布源码后安装 timer，先观察一次真实空闲维护；核对微信登录、原未知审计不变、容量、桥就绪与自然流量，不额外发送消息。工作区与 GitHub 对齐。
