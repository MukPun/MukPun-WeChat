# 文字发送确认与恢复

Native 的服务器接受回执与本地消息投影可能先后写入。桥通过同一发送 ID 等待投影，再核对账号、会话、方向、真实自身身份、正文和服务器 ID。确认 GET 的传输故障最多重试三次，每次仍受原有 40 秒发送期限约束；发送 POST 始终只提交一次。最终投影读取失败也会返回明确的确认结果，避免异常直接终止工作进程并遗失已接受的回执。

新文字审计同时记录 Native 进程 PID、启动标识及当时分段上限。若控制器退出时审计仍是 `submitted` 或 `unknown`，启动会在持有桥锁、旧工作进程全部停止的条件下，通过 GET 读取该发送及其指定的投影。自动恢复要求同一 Native 实例、同一账号和发送 ID、目标摘要、正文 UTF-8 长度和摘要、有效服务器及客户端回执、出站文字身份，以及投影服务器 ID 全部一致。

恢复只覆盖能证明整个动作已完成的第一段短文字：正文长度须小于审计分段上限减 4 字节，且当前配置与审计分段上限一致。完整 UTF-8 分段的首段最多会空出 3 字节，因此该条件排除了多段动作的第一段。其他段、多段边界、缺少新绑定字段的旧审计、结果未知或任意核对不符，仍由原有待核对保护拦截。

核对通过后，桥先备份原审计及 SQLite，再仅更新对应的 OneBot 去重结果和稳定出站消息 ID，最后将审计标记为已接受。若数据库提交后、审计写入前再次退出，下次核对会复用相同结果完成记录。其他未知动作、媒体审计、输入队列、消息映射及微信登录不变；恢复不会重新发送消息，也不代表收件人已读。

私有状态目录下的 `text-recovery/` 保留最近三份已完成恢复备份；同一审计的重试复用原备份，中断恢复的备份会保留供核对。结果冲突会在备份前拒绝。`last-forwarder-failure.json` 单独保存最近一次运行失败的固定原因码，启动保护失败不会覆盖它。未完成确认的审计另存 `confirmationCode`，不写消息正文或凭据。
