# 发送结果按动作隔离

用户已批准：消息发送失败或结果未知不能令整个桥停摆，所有异常结果保留日志供后续排查。沿用真实成功语义；不采用提交即成功，也不自动重发未知动作。

## 行为与职责

- core 保存每笔动作结果与幂等缓存。1408 保持未知，但不再因此关闭全局 send_hold 或事件发布；重复原动作仍返回原结果，不再次提交。
- runtime 收到普通失败/未知报告只记录诊断和计数。待决文本关联采用有界缓存，晚到回执只修正精确绑定的原动作，不影响后续动作。显式完整性保护仍可关闭准入。
- 微信适配器保留已有 Native 回执/图片投影检查及按作业隔离账本。新作业不得覆盖未持久保存的未知证据。Native 判为 failed/readback 或语音部分处理失败，但缺少严格未提交证明时，按精确绑定转为 unknown；不因此伪造失败或停止控制器。身份、存储或 IPC 完整性故障仍按原规则处理。
- host 超时后，root 尚在处理旧请求时，后续合法发送返回单笔资源忙拒绝，不能触发控制器异常、覆盖旧审计或并发提交。Native 完成后自然接受新动作。媒体晚到回执按原请求/类型/目标/源摘要接收，不串给后续请求。
- 图片/语音分块组装在Native主循环主动检查原有期限，即使取消后不再到达分块也释放槽位并返回明确未提交的超时结果；迟到分块按退休请求丢弃。保留原分块到达时的期限检查和所有资源预算。
- 不新增发送队列或无限后台轮询；复用已有有界 Native 查询与文本晚到回执。媒体晚到结果只保存 Native 审计/日志，不自动改写已返回的未知动作结果；文本完整单段回执仍可精确 CAS。worker 重建仍须证明旧进程退出、未知证据已落盘；未知结果报告不消费 worker 崩溃预算，工作进程超过有界请求期限仍按故障监督恢复。

## 诊断

root 写入私有 send-outcomes.jsonl，并输出同一结构到 stderr/journal。记录时间、层、类型、成功/拒绝/未知/晚到状态、固定错误码、请求/作业关联、目标与内容摘要、字节数及处置类别。禁止正文、URL、base64、token、原始 echo、异常原文和真实联系人 ID。每文件 1MiB，共四份，达到限制原子轮转；保留原 SQLite 动作结果、Native 账本与恢复审计，不以日志轮转清除它们。

控制器与 capture 子进程共用私有 flock，覆盖检查、轮转、追加和 fsync。普通动作拒绝也保留固定错误码，不写原始异常内容。完整异常审计及 recovery marker 在覆盖实时槽位前保存到 `send-outcome-evidence.json`（最多128笔/1MiB）；日志可轮转，完整证据不能随之删掉。预留容量同时计入处置账本、完整证据和未结算数；不足只拒绝新发送，保留接收。

## 恢复与范围

历史人工隔离、旧恢复清单、账号会话和未知图片均保持；不借用旧批准重发或改成失败。普通已持久隔离的发送结果不再作为运行期交付门禁。恢复清单缺证、身份变化、审计无法落盘等仍是独立完整性问题。

Native 仍 queued/running 等合法非终态时，`PendingSend` 是专门分类，不包装为归档损坏。`pending-send-outcomes.json` 保存最多32笔/256KiB，绑定原Native PID/ticks及完整审计；只能证明当前会话中该请求已保存，不能作为恢复许可。后台固定副本建立后、两worker恢复准入前结算；终态按原证据规则登记，完整归档后才移除pending，且不能覆盖后来已复用实时槽位的新审计。未终态延后本轮捕获30秒；原去重结果不重发，也不因结算而乐观改成功。

捕获复制后可恢复收发，因此后续正常新增账本/pending必须使旧候选作废。仅同profile、原entries完整保持、revision精确递增的追加允许延后；原条目变化、身份/回放边界错等保持保护。`PublishDeferred` 只在证明当前指针尚未改变时传播，不能把未知提交或fsync失败降为正常延后；候选不推进保护下界。

参考固定 NapCatQQ 72912f2 的 OneBotAction 动作异常边界与日志职责；保留微信专有单次提交、作业关联和持久恢复证据。

本轮先完成本地源码与合成验证；不执行旧暖恢复工具，不自动启动当前门控失败的生产桥，不增加真实微信消息或模型调用。

## 文件边界

- `core/sending.py`：动作结果、幂等与原单次提交，不控制普通错误的全局暂停。
- `adapters/wechat/proxy.py`：有界退休请求，取消到finally之间以及之后的回执/ACK仍严格绑定旧请求。
- `adapters/wechat/native.py`：空闲管道上的媒体组装到期释放，不依赖下一帧触发。
- `runtime/reports.py`、`session.py`、`output.py`、`state.py`、`broker.py`：诊断、准入和单请求串行；资源忙不覆盖旧审计。
- `runtime/outcomes.py`：唯一诊断格式、私有日志锁/轮转。
- `scripts/pending_send_outcomes.py`、`recovery_dispositions.py`、`run_private_forwarder.py`、`voice_forwarding.py`：完整证据、合法非终态、持久保存与恢复资格的区别。
- `recovery_checkpoint.py`、`recovery_capture_worker.py`、`recovery_manifest.py`、`runtime/capture_job.py`：固定副本结算、证据CAS、未提交候选延后。
- `runtime_manifest.py`及两受限runner：显式源码/测试交付，不递归收集私有目录。

## 验证

用真实 SQLite/合成 IPC 复现文本、图片、语音未知后下一动作和入站可继续、原动作不重发；覆盖旧回执晚到与新请求并行等待、错误绑定拒绝、root 忙拒绝不覆盖旧审计、普通错误报告不暂停、日志脱敏/轮转/重新读取以及现有恢复账本不变。相关受限 runner/源码清单同步；不重复无关全量验收。
