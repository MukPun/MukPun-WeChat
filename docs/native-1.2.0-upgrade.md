# Native v1.2.0 升级与验证

> 实施流程：按 writing-plans / executing-plans 逐项执行；独立代码审查后提交。本文不构成线上切换完成记录。

**目标：** 将正式 Native 工具升级到已核对的上游 v1.2.0，保留当前桥能力、资源限制、登录资料和发送审计。

**方案：** 以正式发布资产为版本依据；先完成离线兼容性和受限环境验证，再考虑线上切换。若新版仍存在已知图片准备缺陷，单独记录、复现和审查补丁，不将版本升级等同于该缺陷已修复。原未知图片仍按现有隔离与去重规则处理。

**技术：** Python 3.12、OneBot v11、固定 Rust Native、Linux systemd/cgroup 与匿名 IPC。

## 回归范围与验收边界

版本绑定回归核对正式资产文件名、Native 预期版本、上传资产大小与 SHA256 在各入口一致；错误资产仍应被拒绝。Python 回归覆盖文本/图片、群和指定私聊、真实 @、成员名称、SSE 游标、去重、防循环、动作回执、IPC、预算与会话恢复。

Linux 受限验证保留现有 CPU、内存、tasks、tmpfs、文件和网络限制。空环境验证不能使用生产 token、微信资料、真实模型或真实发送，也不能证明某一微信账号已经迁移成功。

线上验证复用正常自然流量；不额外发送诊断图片或调用模型。只读就绪状态、受限模拟及旧版本的实际交付均不等于新版本的真实交付。

## 当前线上边界

升级检查时，桥、SSE 和 AstrBot 均就绪；新图片审计为 accepted，队列无 publishing/uncertain，旧约 27KB 图片仍为 unknown。现有隔离记录绑定当前 Native 实例，常规恢复会拒绝该未决作业。不得为升级而删除作业、改成失败、重发图片、隐式 fresh login 或跳过恢复检查；如需改变跨 Native 的隔离策略，必须先形成可审查方案和验证证据，再取得对应授权。

## 验证结果

接口核对发现新版删除了 `GET /messages/{id}/quote`。现改读父消息详情的 `quote` 字段，仅接受同账号、同会话、同父消息且 `type=49`、`appMessageType=57`、引用为 `type=3/state=embedded/embeddedImage=true` 的情况；再以父消息 ID 读取其媒体。撤回、缺失、非图片或外部会话引用明确拒绝，不检索历史原始消息替代收到的引用内容。此行为与新版 `quotes.rs`、`profile.rs` 及媒体解析一致。

版本绑定测试先在 beta.8 配置下失败，再在三个入口同步后通过；引用图片的新路由断言也先确认旧实现失败，随后图片模块 19 项、跨工作进程模块 17 项通过。完整合成回归 719 项通过；OneBot 模拟通过；Linux 受限回归 309 项通过、零跳过，8 项隔离检查通过，测试单元清理完成，线上 Native 身份、Docker/FRP 业务进程及宿主网络保持不变。

空客户端 shell 入口同步新版资产路径、SHA256、精确大小和只允许复制该大小的暂存文件保护；运行单元的 CPU、内存、文件及网络限制不变。大存储验证改用当前 Git 源码与统一资产路径，不再将当前校验器与 beta.8 资产混用。尚未完成的项目继续保留未勾选状态。

官方资产已完整下载并核对 34761720 字节及发布 SHA256；作为独立新文件保存在实例资产目录，保留旧二进制。用受限、无账号、无外网的独立环境完成 beta.8 初次启动、恢复到 v1.2.0、再次 v1.2.0 冷恢复三阶段验证：账号数始终为 0，API/storage/cursor 密钥保留，快照与清理通过，测试资料已移除。生产 Native 身份、Docker/FRP 业务及宿主网络保持不变，微信请求、消息发送和模型调用均为 0。

更新后的空客户端 shell 已实际验证 Native 1.2.0、匿名账号访问被拒、账号列表为空及子进程停止；全部隔离检查通过。初次验证发现 GNU install 在精确文件大小上限处继续探测 EOF 导致 SIGXFSZ；改为在同一精确上限内复用既有有界复制器及完整摘要校验后通过，没有提高运行资源限制。

新版 `image_variants` 和 `fit_jpeg` 与 beta.8 逐字一致，锁定的 image 库均为 0.25.10。已有图片变体放大问题不能视为随版本更新修复；旧 beta.8 候选补丁不作为正式 v1.2.0 资产的一部分。此项故障仍需单独处理，不影响本次已验证的版本和接口兼容性结论，也不构成任意素材发送成功保证。

更新后的大存储入口也已在 v1.2.0 下完成实际离线验证：128MiB 私有卷中保存、恢复并核对 40MiB 合成文件，密钥保留、清理与业务/网络基线检查通过。没有账号登录或二维码流程，生产会话所有者未变。

## 线上跨版本隔离迁移方案（用户已授权）

当前隔离只绑定原 Native PID/启动 ticks，直接更换 Native 会被现有门禁拒绝。常规升级仍遵守该门禁；上述离线通过不授予跨实例绕过权限。若用户进一步授权此迁移，先实现并回归以下精确例外，再考虑切换：

升级代码保留在独立 Git 工作树；线上主检出继续使用已验证的 `ad92742`，以免桥自动重启时提前加载新旧混合代码。不能把对线上目录执行 git pull 当作已完成 Native 迁移。

1. 在桥无待发送动作、无 publishing/uncertain 入站时，备份完整配置、审计、预算、桥数据库和保存资料；保留原 Native 版本及所有原始记录。
2. 新恢复检查只允许已隔离那一笔完整绑定的 `needs_review/submitting`、`retryable=false` 作业继续保持未知；核对账号、目标、源、幂等键及保存内容，不改作业状态、不进入发送队列。任何其他待发或未知动作仍拒绝恢复。该例外不得扩展普通恢复入口。
3. 只停止本项目桥及 Native，复用原完整资料启动 v1.2.0；不 initialize、扫码或登出。核对保存身份、密钥、审计和不可重试状态后，才将精确隔离重新绑定到新 Native 实例并启动桥。失败时保留资料和证据，不自动重试发送。

迁移后只读检查就绪、SSE、AstrBot 和自然流量，不增加诊断发送或模型调用。生产切换、跨实例隔离例外及新版本真实交付目前均未完成，不能宣称全部线上功能已经验收。

## 迁移实现与真实资料断网验证

用户已明确授权开始迁移。新增恢复例外仅经显式迁移入口传入：普通恢复不读取票据，仍拒绝任何待发送或未知作业。迁移只放行账号目录和完整行摘要匹配的唯一 needs_review/submitting、attempts=1、cancel_requested=0、retryable=0 图片作业，作业不更新、不重新入队。额外作业、待发文字、WAL 待发记录、绑定改变或作业缺失均阻断恢复。

resume_quarantined_native.py --serve 读取 root 私有单次票据，以排他文件锁覆盖票据消费和所有者完整生命周期；实际复制到受限环境的归档流必须匹配票据 SHA256。隔离行检查在 Native 启动前执行。原控制器、Native PID、cgroup 及私有目录检查保留；只额外接受同检出中该迁移入口的精确 owner argv。

真实账号的完整保存副本在断网受限环境中验证时，发现新版 wechat-store/admission.rs::open_prepared 会创建两份 SQLite 校验副本。当前约 47MiB 的控制库因此在原 128MiB 卷中触发 copy_file_range 的 ENOSPC；空账号验证无法覆盖该问题。现将私有卷限定为 192MiB，Native 256MiB、父 cgroup 384MiB、单文件 128MiB、保存资料 128MiB 上限均保持。图片准入扣除额外 64MiB 和两份当前数据库副本中更大的预留，新上传增长也同时预留其两份副本；存储不足时明确拒绝，不能用图片填掉下次启动的空间。

在保留原内存硬限制的 192MiB 卷中，真实保存副本已恢复为一个离线账号；API、storage、cursor 密钥一致，旧未知图片完整行不变，临时环境清理与原生产 Native、宿主网络和 Docker/FRP 业务基线检查通过。只在该离线副本回收一个有完整成功回执的旧上传源缓存，未改原生产资料。未登录、未扫码、未发送消息、未调用模型。这项证据仍不等于线上账号已经连接，线上切换结果须另行记录。
